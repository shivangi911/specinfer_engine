## 1. System Architecture & Mathematical Foundations

### 1.1 The Memory-Bandwidth Bottleneck in Autoregressive Inference
Autoregressive language model generation emits tokens sequentially: generating token $t_{n+1}$ requires passing the entire parameter set $W \in \mathbb{R}^{d_1 \times d_2}$ from memory into compute logic. For a 32B parameter FP16 model ($64\text{ GB}$ parameter footprint), emitting a single token requires transferring $64\text{ GB}$ over the memory bus.

* **Compute-Bound Regime (Prefill Stage):** Processing an input prompt of $N$ tokens in parallel saturates compute units (high Arithmetic Intensity: $\text{FLOPs} / \text{Byte} \gg 1$).
* **Memory-Bound Regime (Decode Stage):** Emitting one token at a time results in extremely low Arithmetic Intensity ($\text{FLOPs} / \text{Byte} \approx 1$), making execution memory-bandwidth constrained.

### 1.2 Mathematical Formulation of Speculative Decoding
Speculative Decoding bypasses the memory-bandwidth bottleneck by leveraging two models:
1. **Draft Model ($M_D$):** A small, high-throughput model (e.g., Qwen2.5-0.5B) generating $K$ candidate tokens autoregressively.
2. **Target Model ($M_T$):** A large, high-capacity model (e.g., Qwen2.5-32B) verifying all $K$ candidate tokens in **a single parallel forward pass**.

Let $x_1, x_2, \dots, x_K$ be the candidate token sequence generated by $M_D$, with draft probabilities $q_i(x_i) = P_{M_D}(x_i \mid x_{<i})$.
The Target Model $M_T$ evaluates the sequence in one forward pass, yielding target probabilities $p_i(x_i) = P_{M_T}(x_i \mid x_{<i})$ for all $i \in \{1, \dots, K+1\}$.

#### Modified Rejection Sampling Algorithm
To guarantee that the final output distribution matches the target model $M_T$ exactly (unbiased sampling), each draft token $x_i$ is evaluated sequentially for $i = 1, \dots, K$:

1. Calculate Acceptance Probability:
   $$\mathbb{P}(\text{accept } x_i) = \min\left(1, \frac{p_i(x_i)}{q_i(x_i)}\right)$$

2. Draw uniform random variable $u_i \sim U(0, 1)$.
   * **If $u_i \le \mathbb{P}(\text{accept } x_i)$:** Token $x_i$ is accepted. Proceed to evaluate $x_{i+1}$.
   * **If $u_i > \mathbb{P}(\text{accept } x_i)$:** Token $x_i$ is rejected. Discard candidate tokens $x_i, x_{i+1}, \dots, x_K$.

3. Resampling Step on Rejection:
   If token $x_i$ is rejected at index $n$, resample a replacement token $x_n'$ directly from the adjusted probability distribution:
   $$p'_n(x) = \frac{\max(0, p_n(x) - q_n(x))}{\sum_{y} \max(0, p_n(y) - q_n(y))}$$
   Terminate the draft verification cycle and emit accepted tokens $x_1, \dots, x_{n-1}$ followed by $x_n'$.

#### Mathematical Proof of Distribution Guarantee
$$\mathbb{P}(x_i = x) = q(x) \cdot \min\left(1, \frac{p(x)}{q(x)}\right) + \left(1 - \sum_y q(y) \min\left(1, \frac{p(y)}{q(y)}\right)\right) \cdot \frac{\max(0, p(x) - q(x))}{\sum_y \max(0, p(y) - q(y))} = p(x)$$

Thus, the speculative decoding emission probability distribution is **mathematically identical** to standard autoregressive sampling from $M_T$.

### 1.3 Theoretical Speedup Formula
Let $\alpha$ be the average token acceptance rate ($\alpha \in [0, 1]$), $K$ be the draft lookahead window size, $c_D$ be the cost per token of $M_D$, and $c_T$ be the cost per forward pass of $M_T$:

$$\text{Speedup } S = \frac{1 + \alpha K}{c_D \cdot K + c_T}$$

When $\alpha > 0.70$ and $c_D \ll c_T$, the expected latency per generated token drops by $2.5\times \text{ to } 3.8\times$ on Apple Silicon unified memory architectures.

### 2.1 Component Specifications

#### 1. FastAPI Proxy Gateway & Async SSE Streamer
* Handles incoming OpenAI-compatible `/v1/chat/completions` API calls.
* Manages asynchronous Server-Sent Events (SSE) streaming connections to stream verified tokens back to the caller in real time.

#### 2. Semantic Vector Cache Subsystem
* Embeds prompts using `nomic-embed-text` into a 768-dimensional vector space.
* Measures Cosine Distance against an embedded Qdrant collection:
  $$d_{\text{cosine}}(q_1, q_2) = 1 - \frac{q_1 \cdot q_2}{\|q_1\|_2 \|q_2\|_2}$$
* If $d_{\text{cosine}} < 0.05$, the gateway streams the cached completion immediately, bypassing GPU execution ($0\text{ms}$ model inference time).

#### 3. Dual-Model Unified Memory Manager
* Loads both $M_D$ (0.5B) and $M_T$ (32B) into Apple Silicon Unified RAM using Metal Performance Shaders (`mlx` / `mlx-lm`).
* Zero-copy architecture ensures tensors are accessed directly by both CPU and GPU blocks without host-to-device PCIe transfer overhead.

#### 4. Shared KV-Cache Synchronizer
* Maintains alignment between $M_D$'s KV-Cache and $M_T$'s KV-Cache.
* When $M_T$ rejects draft tokens starting at index $n$, the KV-Cache Manager truncates the cache pointers for both models back to state $n-1$, avoiding state corruption.

#### 5. Tensor Rejection Sampler
* Computes vector ratio $\frac{p_i}{q_i}$ across candidate logits.
* Applies vector mask operations to identify accepted token sub-sequences and handles modified resampling on rejected indices.

## 8. Senior ML Engineer Interview Defense & Talking Points

1. **How do you mathematically guarantee that speculative decoding does not degrade model quality?**
   * *Answer:* Speculative decoding uses modified rejection sampling. The acceptance condition $\mathbb{P}(\text{accept } x_i) = \min\left(1, \frac{p_i(x_i)}{q_i(x_i)}\right)$ and the resampling distribution $p'_n(x) = \frac{\max(0, p(x) - q(x))}{\sum_y \max(0, p(y) - q(y))}$ ensure that the marginal emission probability for every token evaluates to exactly $p(x)$, which is the target model's raw probability distribution.

2. **Why does speculative decoding provide higher speedups on unified memory architectures than discrete GPUs?**
   * *Answer:* M-Series Macs share unified memory between CPU and GPU with memory bandwidth limits (e.g., $150\text{ GB/s}$ to $400\text{ GB/s}$). Because autoregressive decoding is memory-bandwidth bound, reading 32B parameters for every token caps output speeds. Speculative verification reads the 32B parameters once to process $K$ tokens in parallel, converting a memory-bound decode pass into a compute-bound matrix operation.

3. **What happens to the KV-cache when a draft token is rejected at position $n$?**
   * *Answer:* When rejection occurs at index $n$, tokens from $n$ to $K$ are invalidated. The KV-cache synchronization layer truncates the sequence length pointers for both the draft and target models back to $n-1$. The resampled replacement token $x_n'$ is then appended, keeping KV-caches synchronized without re-evaluating preceding tokens.
